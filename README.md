# 德州供应商重污染减产监督台

> 每天巡检德州市生态环境局「重污染天气信息发布」栏目，下载应急响应公告原文，
> 结合《重污染天气应急减排清单》判定**在监控供应商会被限产多少**，
> 生成供应商风险 + 反制囤货动作 + 污染/气象可视化，发布为静态站点。

- 数据源：德州市生态环境局（公告 + docx 附件）、WAQI（AQI）、Open-Meteo（污染/气象，免 key）、OpenStreetMap（底图，免 key）
- 运行方式：GitHub Actions 每天 3 次（07:30 / 13:30 / 19:30 北京时间）巡检，结果提交回仓库并部署 GitHub Pages
- 公告没更新时**不重新总结**，页面继续显示上一次的 AI 总结，只更新时间戳和污染数据

---

## 1. 结论示例：山东军高过滤材料有限公司

数据取自 `2025年12月调整版重污染天气应急减排清单/2-固定源应急减排措施清单.xlsx`：

| 项目 | 内容 |
| --- | --- |
| 地址 | 天衢新区 · 京津冀协同发展产业合作区街道 · 天衢东路6666号（116.335352, 37.186762） |
| 行业 | 玻璃 / 玻璃后加工 |
| 产能 | 过滤材料 1100 万平方米/年 |
| 绩效等级 | **非绩效引领**（不属于 A/B 级或绩效引领企业，橙色预警即执行限产） |
| 橙色预警（Ⅱ级，当前生效） | 吹棉/收棉/固化工序（4条线）停 2 条、复合工序（2条线）停 1 条、缝纫工序（2条线）停 1 条 → 8 条线中 4 条受限，**限产 50%**；厂内运输停国四及以下 |
| 红色预警（Ⅰ级） | 上述工序**全部停产 → 减产 100%** |
| 黄色预警（Ⅲ级） | 正常生产 / 自主减排，**不受影响** |
| 企业侧应急成本 | 清单填报值：橙色预警 21000 元/天，红色预警合计 30000 元/天 |

当前公告《关于启动重污染天气Ⅱ级应急响应的通知-重污染应急〔2026〕23号》（2026-11-02 发布橙色预警，11-03 12 时启动Ⅱ级响应）对应**橙色预警**，
所以：**会受影响，但不是断供，而是产能压降 50%**（吹棉/收棉/固化 4 条线停 2 条、复合 2 条停 1 条、缝纫 2 条停 1 条）。
按历史 25 次同级响应的中位时长 5 天、当前扩散条件「好」修正，**本次预计持续 4 天，2026-11-07 前后解除**。

> 以上全部来自公告 + 官方清单，不含任何需要采购方内部数据的测算。
> 供应商若以「政府要求停产」为由要求涨价、囤货或延迟交付，可用清单原文反制：
> 受限的是**特定工序的部分生产线**，并非全厂停产；限产 ≠ 缺货，也 ≠ 涨价依据。

## 2. 快速开始（本地）

```bash
pip install -r requirements.txt
python run.py              # 抓取 + 分析 + 生成 docs/
python run.py --force      # 公告未更新也强制重新分析
python run.py --offline    # 不联网，仅用上次数据重建页面（调前端用）
python run.py --snapshot   # 从 Excel 重建内置企业快照（一般不需要跑）
python run.py --probe      # 检查数据源可达性（DNS/代理/HTTP）

# 预览
cd docs && python -m http.server 8765     # 打开 http://127.0.0.1:8765
```

**不需要上传 Excel**：在监控企业的清单数据已抽成 `data/suppliers_snapshot.json`（5KB，随仓库提交），
程序优先读快照；只有在新增企业、想换成新版清单时，才把 Excel 放到
`2025年12月调整版重污染天气应急减排清单/` 下执行一次 `python run.py --snapshot`。

生成物：

```
data/latest.json                最新一次结论（前端唯一数据源）
docs/data/latest.json|.js       同上，供前端读取/内联
data/state.json                 上次处理过的公告 id（判断"是否更新"）
data/history.json               公告时间线
data/suppliers_snapshot.json    内置企业清单快照（不需要 Excel）
data/air_history.json           9 个网格点的历史空气质量缓存（阈值用，7 天刷新）
data/raw/<公告id>/              公告正文 + 附件原文（留证）
docs/                           可直接部署的静态站点
```

## 3. 部署到 GitHub

1. 新建仓库并推送本目录（不需要 Excel 清单，`data/suppliers_snapshot.json` 已含所需企业数据）。
2. **Settings → Secrets and variables → Actions** 添加（都可选）：
   - `WAQI_TOKEN`：WAQI 的 token（不配则用 `config/settings.yaml` 里的默认值）
   - `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL`：任意 OpenAI 兼容接口（DeepSeek、智谱、OpenAI…）
     - 例：`AI_BASE_URL=https://api.deepseek.com/v1`、`AI_MODEL=deepseek-chat`
     - **不配也能跑**：自动回退到规则引擎，输出结构完全一致，只是文字不如大模型细腻
   - 邮件通知（见 3.1，全部可选项）
   - 源站中继已在 `config/settings.yaml` 内置（免费 Cloudflare Worker），开箱可用；
     更换/重建见 [DEPLOY.md 第 6 节](./DEPLOY.md)。
3. **Settings → Pages → Source** 选 **GitHub Actions**。
4. 手动跑一次 `Actions → 每日重污染巡检 → Run workflow`，之后每天 07:30 / 13:30 / 19:30 自动执行。
   勾选 `notify_test` 可先发一封测试邮件验证 SMTP。

工作流会：抓取 → 分析 → 生成 `docs/` → 发送邮件 → 提交回 `main` → 部署 Pages。

### 3.0 用 Vercel 部署（推荐）

仓库根目录的 `vercel.json` 已配好：不构建、直接托管 `docs/`。

1. Vercel → **Add New Project** → 选择仓库；
2. Framework Preset 选 **Other**，Root Directory 默认；
3. Build / Output 不用改（`buildCommand` 为空操作、`outputDirectory` 为 `docs`）；
4. Deploy。之后 `main` 每次提交（含 Actions 写入的数据）都会自动重新部署。

注意：Actions 的提交信息里**不能带 `[skip ci]`**，否则 Vercel 会跳过该提交的部署；
工作流只监听代码路径，所以数据提交不会反向触发 Actions，不会循环。
如果用 Vercel，GitHub Pages 的 deploy job 会自动跳过（需 `DEPLOY_PAGES=true` 才启用）。

| Secrets / 变量 | 说明 |
| --- | --- |

发信策略（避免打扰）：

- **只在两类事件发信**：`startup`（启动/升级响应）、`terminate`（终止响应）；
  `unchanged`（公告未更新）默认关闭，页面数据照常刷新但不发信。
- **同一条公告只发一次**：按公告 id 去重，记录在 `data/notify_log.json`；
  每天跑 3 次（07:30 / 13:30 / 19:30 北京时间）也只会在新公告出现时打扰一次。

# 预览 HTML 会写到 data/email_preview.html，可直接用浏览器打开检查排版

## 4. 分析规则

### 4.1 脚本规则（可复现、可审计，`config/analysis_rules.yaml`）

```
减产幅度 = 清单中该企业「<预警颜色>_管控方式」→ measure_factor 的最大值
           （停产=100%、限产50%=50%、自主减排=5%…）
受限产线 = 清单「生产线、工序」里的总条数 vs 措施文字里停/限的条数
影响程度 = 减产 100% → 全部停产 | ≥50% → 大幅限产 | >0 → 部分限产 | 0 → 不受影响
持续时长 = 历史同级响应的中位天数 + 扩散条件修正（好 −1 / 一般 0 / 差 +2）
                                + 区域联动修正（好 −1 / 一般 0 / 差 +1）
                                （两项合计封顶 −2…+3）
          再与「北京→德州历史关系」推算的日期对齐：
              北京已解除 → 取两者中较早的日期（不早于今天）
              北京仍在响应 → 取两者中较晚的日期
           若已持续天数超过该值 → 改用「比已持续天数更长」的样本估剩余天数并顺延
           已超过历史最长样本 → 不再外推日期，只标注已持续天数，等官方终止公告
```

**明确不做的事**：不估算采购方库存能撑几天、不估算断供缺口、不算风险分。
那需要采购方内部数据（库存、交期、替代供应商、合同条款），程序无从得知；
早期版本里那几个字段是示例值，已全部删除，避免把猜测当结论。

响应天数默认 5 天（`config/settings.yaml → analysis.default_duration_days`），公告写明终止时间时以公告为准。

### 4.2 AI 规则（`src/analyze.py` 中的 system prompt）

只允许依据「公告原文 + 清单措施 + 实况数据」判断，必须区分"政策要求"与"供应商借口"，
输出 JSON：`headline / summary_md / counter_hoarding / alerts / outlook`。
调用失败或未配置 key 时自动回退脚本总结，页面右上角会标注引擎来源。

### 4.3 抓取与"不更新不总结"

- 只处理列表里的**最新一条**公告；列表接口无分页（首页 70 条已含全部）。
- 公告 id 与 `data/state.json` 相同 → 不重新总结，沿用上次 `analysis`，只刷新空气/气象，页面顶部显示
  「⚠ 今日未抓取到新公告，以下内容沿用 YYYY-MM-DD 的分析结果」。
- 即使公告没变，**预计解除时间每天都会重算**（见 4.4）：它取决于「已持续天数」和当前风速，
  不是启动日 + 固定天数的一次性结果；预测日期一变，文字总结会用规则引擎重写（旧 AI 文案里写死的日期会过期）。
- 每天仍然刷新污染与气象数据，趋势图始终是最新的。

### 4.4 历史规律与预计解除时间（`src/history.py`）

栏目里每条公告都会成对出现「启动…级应急响应」与「终止…应急响应」。程序把全部历史公告按时间排序，
还原成一段段响应：

```
启动 2025-12-15 ── 终止 2025-12-20   5 天
启动 2026-01-04 ── 升级Ⅱ级 ── 终止 2026-01-06   2 天
启动 2026-03-09 ── 终止 2026-03-13   4 天
…
```

统计同级别响应的中位/均值/P75/范围，再按当前扩散条件、**区域联动**修正
（扩散：好 −1 / 一般 0 / 差 +2；区域：好 −1 / 一般 0 / 差 +1；合计封顶 −2…+3），
得到本次**预计解除日期**；最后用「北京→德州历史起止关系」（见 4.4.2）交叉校准：
北京已解除时取较早日期、北京仍在响应时取较晚日期。该日期同时作为供应商"影响窗口"的右端点，
页面「历史响应规律」卡片会画出最近 12 次的时长柱状图。

响应拖得越久，"还没结束"的样本就越少，所以每次巡检都会按**已持续天数**重新切片：

```
已持续 6 天，中位 4 天          → 用「>6 天」的样本估剩余天数（剩余中位 2.5 天）
                                 → 8 天后解除（含扩散修正），而不是停在原来的 11-12
已持续 25 天，历史最长 12 天     → 不再外推，页面显示「—」，等官方终止公告
```

因此同一份启动公告，页面上的预计解除日期会随日期推进自动顺延；扩散条件（Open-Meteo 逐时风速）
一次巡检（每天 3 次）刷新一次，风速转好时该日期会提前。

当前样本：25 次Ⅱ级响应，中位 5 天、均值 5.4 天、P75 6 天、范围 2–12 天。

### 4.4.1 区域联动（`src/region.py`）

公告原文写的是「京津冀及周边区域…区域联防联控要求」，解除通常等整个污染过程结束。
只看德州本地风速等于只看半个信号，所以额外统计 11 个同过程城市：

```
城市   = 北京 / 天津 / 廊坊 / 唐山 / 保定 / 石家庄 / 衡水 / 沧州 / 邢台 / 邯郸 / 济南
实况   = WAQI 城市级 AQI（与德州市区同口径）
趋势   = Open-Meteo 区域逐时 PM2.5：未来 24h 中位变化 > +15% 转差 / < −15% 转好
判定   = 差：中位 AQI ≥150 或 ≥半数城市中度污染以上，或仍≥100 且在转差
         好：中位 <100 且至多 1 城中度污染以上、不在转差、且北京 <100（北京是风向标）
         其余为一般
修正   = 差 +1 天 / 一般 0 / 好 −1 天
```

页面「空气质量与扩散条件」卡片会列出各城市 AQI 芯片与一句结论；区域为「差」时也会进告警列表。
一个城市拉取失败不影响整体（失败城市直接剔除），全部失败时退回只看本地扩散条件。

### 4.4.2 北京官方公告联动（`src/beijing.py`）

区域联动用的是空气质量，能说明「区域还在污染」，但说不清**官方口径什么时候解除**。
北京市应急管理局的「预警信息」栏目（[col/col2472](https://yjglj.beijing.gov.cn/col/col2472/index.html)）
把每一次空气重污染预警的发布/启动/解除都挂在同一列表里，标题写的是**实际生效时刻**
（如「于 2026 年 11 月 14 日 24 时解除空气重污染橙色预警」，栏目发布日期却是 11-15）。
页面末尾还有一个隐藏的 `<abbr id="json">`，内含整栏 2000+ 条的 JSON 数组，直接解析它比爬列表稳定。

```
抓取   = GET 栏目页 → 取 <abbr id="json"> 的 JSON 数组（直连即可，不需要德州那套中继）
筛选   = 标题含「空气重污染」，且含 发布/启动/解除/终止
时刻   = 解析标题里的「YYYY年M月D日H时」；「24时」= 次日 0 时；无时刻时退回发布日期
配对   = 启动 → 解除 还原成一段预警（同日升级只提级，不新开一段）
状态   = 最近一段未解除 → 响应中；已解除 → 已解除（含持续天数、解除后第几天）
关联   = 与德州本次响应窗口 [生效时刻, now/终止] 按日期取交集
```

**北京与德州的历史起止关系（预测依据）**：把北京历次预警与德州历次「启动→终止」按启动日配对
（相差 ≤3 天视为同一轮区域污染过程，取时间最近的北京预警），统计两个滞后：

```
启动滞后 = 德州启动日 − 北京启动日
终止滞后 = 德州终止日 − 北京解除日（两端齐全才计入）
样本     = 启动滞后 4 次（中位 −0.5 天，范围 −3…0）；终止滞后 2 次（中位 +2 天，范围 +1…+3）
预测     = 北京解除日 + 终止滞后中位 = 德州预计解除日
           北京仍在响应 → 北京启动日 + 北京持续中位（3 天）+ 终止滞后，锚点不早于今天
校准     = 北京已解除：预计解除取「时长模型」与「关系推算」中较早者（不早于今天）
           北京仍在响应：取较晚者
           北京解除超过 3 天德州仍未终止：关系信号失效（两地脱钩），只用时长模型
```

页面「北京官方动态」卡片显示北京最近一次空气重污染预警的状态、持续天数、与德州的时间重叠结论、
历史滞后统计与「按北京关系推算」的日期（可展开看逐次配对），并列出最近 8 条相关公告
（标注哪些落在德州本次响应窗口内），每条都可点回北京原文。

当前实例：北京 11-09 启动、11-15 解除（6 天）；德州 11-09 20:00 启动至今未终止。
可配 4 次（启动日相差 ≤3 天），其中 2 次两端齐全——德州终止比北京解除晚 1 天（2025-12）与 3 天（2024-11），
中位 2 天 → 关系推算 11-17，与时长模型一致，最终预计 11-17。

### 4.5 可视化数据

- **多污染物逐时曲线**：PM2.5 / PM10 / O₃ / NO₂ / SO₂ / 沙尘（左轴 μg/m³）与 CO（右轴 mg/m³），
  过去 24h + 未来 48h，图例可逐项开关（CO 默认关闭）。
- **监测站地图**：WAQI `map/bounds` 接口取德州市域及周边 70+ 个站点，按 AQI 着色打点，可点击看站名/时间；
  另以站点为圆心、按 AQI 放大半径绘制**污染区（示意）**，表示影响范围量级（非实测边界），可在图层控件里开关。
- **扩散条件**：Open-Meteo 10m 风速（<2 差 / 2–4 一般 / >4 好），用于判断响应会延续还是提前解除。
- **区域联动**：WAQI 11 个京津冀及周边城市级 AQI + Open-Meteo 区域 PM2.5 预报，见 4.4.1。
- **北京官方动态**：北京市应急管理局「预警信息」栏目的空气重污染预警，与德州本次响应做时间重叠比对，见 4.4.2。

### 4.6 证据链与界面

页面每一项结论都标了来源，分三类：

| 标注 | 含义 | 例 |
| --- | --- | --- |
| 官方原文 | 政府公告 / 减排清单里的原值，可直接核对行号与列名 | 「橙色预警_减排措施*」第 2434 行 = 吹棉、收棉、固化工序（2条生产线）停产 |
| 算术合成 | 对原值做的明确运算 | 8 条线中 4 条受限、日成本 7000+7000+7000、减产 50% 按产线加权 |
| 推算 | 模型估算，非官方公布 | 影响时长 4 天 / 预计解除 2026-11-07 |

界面：

- 采用 App Shell：桌面端左侧边栏切换页面，手机端底部标签栏（4 个标签），内容按视图切换而非长滚动；手机端表格自动变卡片列表，带安全区适配。
- 响应式：≤980px 顶栏自动改为两行（品牌一行、控件一行），标题不截断；段导航可横向滑动；≤560px 进一步压缩留白。
- 视觉走 Apple / Tesla 语言：白色卡片 + 极轻阴影 + 大圆角，灰阶层级清晰，数字大而克制，
  分段控件切换语言，图表用细线与浅网格，地图瓦片失败时显示可重试的提示而不是空白。
- 重复内容已合并：结论里不再重复列明细表（由 03 承担）、供应商详情并入明细表、证据链可折叠。
- 默认英文，右上角「中文 / EN」可切换，选择记在 localStorage；英文版的分析正文由后端同时生成
  （规则引擎中英各一份，大模型需在 JSON 里返回 `en` 对象），企业名、公告标题等官方原文保持中文原样。
- 静态资源带版本号（`style.css?v=`、`app.js?v=`、`data/latest.js?v=`），改完刷新即生效。
- 「证据链」卡片逐条列出：字段 / 数值 / 类型 / 依据（文件名›工作表›行号›列名，或公告链接）/ 原文或计算式。
- 底部「数据来源」列出公告、清单（含内置快照版本日期）、WAQI 站点与时间、Open-Meteo 变量、OpenStreetMap 瓦片。
- 公告是「终止响应」时，页面切到"解除"状态：影响、时长、成本一律显示 —，窗口标「已于 … 解除」。

### 4.7 预警阈值参考（`src/thresholds.py`）

用历史数据反推，而不是拍脑袋：

1. 取德州市域 **3×3 共 9 个网格点**近 4 年的逐时 AQI（Open-Meteo 再分析/预报模型，非国控站原始值），汇总为日均；
2. 把每个「启动」公告的发布日（及前一日）标为正样本，Ⅱ级与全部两套口径都算了；
3. 对「日均 AQI ≥150 的网格点数」0…9 逐个作为判别阈值扫一遍，取 F1 最高者；
4. 同时用「全市 3 日滑动均值 AQI」做交叉验证，并给出公告日的中位数与 P25/P75。

当前结果：Ⅱ级发文当日的超标网格点中位 6.5/9；F1 最优警戒线 4/9（召回 62%、精确 8%）。
精确率低说明**单靠空气质量无法判定是否发文**（还要看预报会商与区域联防），
因此页面把「4 个点」定位为关注线，并辅以未来 48h 预报峰值与实时站点超标数作为提前量。
页面对这部分统一标注为「推算」，不属于官方阈值。

### 4.8 近期复警概率（`src/outlook.py`）

「概览」抬头右侧显示未来 **72 小时**再次发布预警的概率，用可解释的四因子加权：

| 因子 | 权重 | 计算 |
| --- | --- | --- |
| 污染峰值 | 40 | 预报 AQI 峰值相对历史阈值（默认 135）的偏离 |
| 持续累积 | 25 | PM2.5 超过 75 μg/m³ 的小时数（24h 记满） |
| 静风 | 20 | 风速 <2 m/s 的小时占比（扩散差） |
| 湿沉降 | 15 | 72h 累计降水（5mm 以上视为明显清除） |

概率 = 四项加权分之和（限制在 3–95%），分档：低 <25 / 中等 25–49 / 偏高 50–74 / 高 ≥75。
面板下方逐条列出每个因子的贡献分，便于判断是哪一项在推高概率；
数据全部来自 Open-Meteo 预报与 4.7 的历史阈值，页脚口径标注为「非官方预测」。

## 5. 增删供应商

编辑 `config/suppliers.yaml`：

```yaml
suppliers:
  - name: 山东军高过滤材料有限公司   # 必须与减排清单「企业名称」一致
    alias: [军高过滤, 军高]          # 可写简称
    product: 过滤材料（玻纤棉、滤袋）  # 仅用于页面描述
    contact: 采购-过滤材料组
```

只需要企业名（用于在官方清单里匹配），不需要填任何内部经营数据。
匹配不到会在日志里提示，并在页面显示「暂无匹配到的供应商」。

## 7. 说明与边界

- WAQI 返回的是**分指数（IAQI）**，项目按 HJ633-2012 反推为 μg/m³，与国控站原始浓度可能有小偏差。
- 扩散条件用 Open-Meteo 10m 风速判定（<2 差 / 2-4 一般 / >4 好），仅作趋势参考。
- 底图为 OpenStreetMap 免 key 瓦片：默认走德国 / 日本 / 法国镜像（国内直连更稳），失败自动切换并给出重试提示。
- 本工具只做**辅助决策**：签约、索赔、拒收前请以政府公告与清单原文为准。
